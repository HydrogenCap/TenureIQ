## Headline findings (all fixed on this branch)

1. **P0 — The RLS migration chain had never applied.** `shareholders`, `mortgage_events` and `units` have no `organisation_id` column but sat in the four-policy template array; policy creation raised `undefined_column` at migration 2 of 25, aborting the chain. `reminders` had no `deleted_at` yet either. Empirically confirmed by replay; the chain now applies end-to-end. The tenant-isolation e2e spec was always deferred ("needs live Supabase"), which is how this survived.
2. **P0 — No navigation and no sign-out.** The app shell rendered a bare header; all 16 sections were reachable only by typing URLs. Fixed with a top nav + sign-out action.
3. **P0 — Zero error boundaries.** Any server error rendered Next's raw error screen. Fixed (`global-error`, per-group `error.tsx`).
4. **P1 — Invitation self-escalation.** The invitee UPDATE policy allowed changing any column of one's own invitation — including `role` → `owner` — before accepting. Fixed with a column-guard trigger; regression-tested.
5. **P1 — Orgs could never grow.** Invitations were only ever *consumed* (onboarding); no UI or action existed to create one. `/settings/members` now provides invite / revoke / role change / remove.
6. **P1 — `enqueue_compliance_reminders` used invalid PL/pgSQL** (`get diagnostics v = v + row_count`) — the M6 reminder engine would have failed on first cron run.
7. **P1 — Service-role JWT detection was wrong everywhere** (`claims ? 'service_role'` tests for a JSON *key*): broke the org-member self-update guard under Prisma/service connections.
8. **P1 — Cross-org FK pollution.** Child tables (`rent_changes`, `maintenance_*`, `placement_count_changes`, `investor_transactions`, `transaction_import_rows`, `transactions`) only checked their own `organisation_id`; a manager in org A could attach child rows to org B parents. Fixed with RESTRICTIVE parent-org policies; regression-tested.
9. **P1 — Transactional RPCs trusted their parameters.** `create_tenancy_rpc` / `create_mortgage_rpc` / `create_aasc_placement_rpc` (SECURITY DEFINER, service role) now re-assert property/unit/contract ownership.
10. **P1 — Lint had been silently broken since the repo began** (legacy `eslint-config-next` imported into flat config). Repaired; the 87 accumulated violations fixed.
11. **M9 DoD gap — closed-area check.** `createPlacement` never consulted `aasc_areas`. Now hard-refuses in closed Serco areas unless explicitly overridden; overrides write an `audit_log` OVERRIDE entry.
